# Bzden4ik Player

Музыка с YouTube за баллы канала Twitch — прямо в OBS. Зритель вставляет ссылку в награду, трек встаёт в очередь и играет на стриме; заказы проверяются (запрещённые слова, AutoMod, лимиты), баллы за отклонённые и сорвавшиеся заказы возвращаются сами.

**Скачать:** [последняя версия](../../releases/latest/download/Player.zip) · [все версии](../../releases)

Пошаговая установка с анимированной копией OBS — на сайте плеера. Кратко — в `README.txt`.

## Что внутри

| Файл | Зачем |
|---|---|
| `redeem-player.html` | док-панель OBS и сам плеер (`?view=player`, копия для стримера — `&role=me`) |
| `server.js` | локальный сервер на `127.0.0.1:8000` |
| `obs-autostart.lua` | скрипт OBS: запускает сервер вместе с OBS и закрывает заказы при выходе |
| `start-server.vbs` | тихий запуск `server.js` без окна консоли |
| `banned-words.json` | списки запрещённых слов |

`data.json`, `data.backup.json`, `plays.json`, `state.json`, `adv.json` — личные данные (история, плейлисты, прогресс, расширенные настройки), папка `debug` — файлы отладки. В репозиторий они не попадают.

Расширенные настройки (заказы `!!play`, права модераторов, заблокированные зрители) открываются в обычном браузере: `http://localhost:8000/redeem-player.html?view=settings`.

## Безопасность

- **Секретов в коде нет.** Client ID Twitch в `redeem-player.html` публичный по устройству OAuth: он есть в каждой ссылке входа и в каждом запросе к Twitch. Токен Twitch и ключ YouTube API у каждого свои и хранятся только на его компьютере.
- **Сервер слушает только `127.0.0.1`.** Запросы с чужих сайтов (в том числе с другого порта localhost) и подмена адреса (DNS rebinding) отклоняются, у страницы панели строгая CSP.
- **Обновления подписаны.** Приложение ставит архив, только если `release.json` подписан ключом автора и каждый файл с ним совпадает. Закрытого ключа нет ни в репозитории, ни на GitHub, поэтому даже взлом аккаунта GitHub не даст подсунуть пользователям свой код.

Нашли уязвимость — напишите в Telegram [@vtuberstand](https://t.me/vtuberstand), не в публичные issues.

## Выпуск новой версии

1. Поменять номер в `redeem-player\server.js` (`APP.version`, например `1.3.0`).
2. Дописать сверху в `Releases.md` раздел с этим номером: `## 1.3.0`.
3. Запустить `publish.cmd`. Он соберёт чистую версию из `redeem-player`, подпишет её и положит в папку `release` два файла: `Player.zip` и `notes.md` (описание из `Releases.md`). Папка `release` в репозиторий не попадает.
4. На GitHub: Releases → Draft a new release, тег — ровно тот же номер (`1.3.0`, без `v`), описание — из `notes.md`, файл — `Player.zip` (имя не менять).

Архив, собранный не через `publish.cmd` (без `release.json` и `release.sig` внутри), приложение не установит. Тег и номер в `server.js` должны совпадать: иначе приложение откажется ставить архив, а уже стоящая версия будет вечно предлагать обновиться.

**Ключ подписи** лежит у автора в `%USERPROFILE%\.bzden4ik-player\release-key.pem`. Его надо хранить с резервной копией и никому не передавать. Если он пропадёт, установленные копии перестанут обновляться сами: придётся создать новый ключ (`node make-release.js --init`), вписать его в `RELEASE_KEY` в `server.js` и попросить пользователей один раз обновиться вручную.
